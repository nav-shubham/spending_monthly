# Refactor & Optimize the UPI Spending Analyzer

You are a Staff Software Engineer and Software Architect. Your objective is **not to add more features**, but to optimize the existing application into a clean, maintainable, high-performance personal finance application.

## Primary Goal

Follow the **80/20 principle**:

* Keep only features that provide significant real-world value.
* Remove features that add complexity without meaningful benefit.
* Prioritize simplicity, maintainability, performance, and user experience over feature count.

---

# Preserve These Core Features

These are the application's core value and must remain:

### Data Import

* Multi-provider import (Paytm, PhonePe, Google Pay, CSV, Excel)
* Import validation
* Duplicate detection
* Incremental synchronization
* Import history

### Database

* SQLite
* Normalized schema
* Proper indexing
* Fast queries

### Merchant Management

* Merchant normalization
* Exact match rules
* Keyword match rules
* Regex rules (advanced users only)
* Manual merchant editing
* Merge duplicate merchants

### Categories

* Custom categories
* Vendor-to-category mapping
* Bulk category editing

### Dashboard

Keep only high-value metrics:

* Total Income
* Total Expenses
* Net Savings
* Budget Status
* Monthly Trend
* Top Categories
* Top Merchants

### Transactions

* Fast search
* Filters
* Sorting
* Transaction details
* Bulk editing

### Budgets

* Monthly budgets
* Budget progress
* Overspending alerts

### Subscription Detection

Keep recurring payment detection.

### Export

Only:

* Excel
* CSV

---

# Remove These Features Completely

Remove any code, UI, database fields, tests, and dependencies related to:

* Spending Forecast
* Linear Regression Forecasting
* CAGR Calculations
* Spending Volatility
* Seasonal Spending Analysis
* HTML Report Generation
* Google Fonts dependency
* Rule execution counts
* Rule last-used timestamps
* Rule conflict statistics (retain only simple conflict handling if required)

These features increase maintenance cost while providing little practical value.

---

# Simplify AI

AI should never be part of the primary workflow.

Workflow should be:

Unknown Merchant
→ Existing Rules
→ Manual Mapping
→ Optional AI Suggestion

AI must:

* be optional
* never block imports
* never be required for normal operation

---

# Simplify Navigation

Reduce the application to these primary sections:

1. Dashboard
2. Transactions
3. Merchants
4. Budgets
5. Settings

Avoid creating separate pages for every feature.

---

# Improve User Experience

Instead of adding new analytics, improve workflows:

* Import Preview before committing
* Undo last import
* Undo merchant merge
* Bulk merchant editing
* Bulk category assignment
* Better search
* Faster filtering
* Keyboard-friendly UI where possible

---

# Improve Architecture

Ensure strict separation of concerns:

UI
↓
Service Layer
↓
Repository Layer
↓
SQLite

Business logic must not exist inside Streamlit pages.

Keep modules focused:

* parser.py
* importer.py
* repository.py
* services.py
* analytics.py
* mapping.py
* export.py

Each module should have a single responsibility.

---

# Performance

Optimize for responsiveness rather than theoretical scalability.

* Cache expensive computations
* Minimize database queries
* Avoid unnecessary recomputation
* Use vectorized Pandas operations where appropriate
* Ensure the UI remains responsive with tens of thousands of transactions

---

# Testing

Remove tests for deleted functionality.

Expand tests for:

* Parser
* Duplicate detection
* Merchant resolution
* Category assignment
* Budget calculations
* Repository layer
* Import workflow

Prioritize meaningful test coverage over the number of tests.

---

# Final Objective

Transform the application into a focused, production-quality personal finance manager rather than a feature-heavy analytics dashboard.

Every remaining feature should satisfy at least one of these criteria:

* Frequently used by users
* Solves a real financial management problem
* Improves data quality
* Improves usability
* Improves maintainability
* Improves performance

If a feature does not satisfy at least one of these criteria, remove it.
